## Сохранение

- localStorage сохраняет прогресс на устройстве.
- autosave.js дополнительно пишет выбранный JSON-файл в поддерживаемых браузерах.
- cloud-sync.js обеспечивает вход Google и отправку событий в Firestore.
- sync-state.js объединяет события, изменения карточек и дневную статистику.
- Firestore хранит события в users/{uid}/decks/{deckKey}/events/{eventId}.
- firestore.rules ограничивает доступ uid текущего пользователя.
- В каждом браузере на каждом устройстве нужен вход в один Google-аккаунт.
- Импорт старого сохранения требуется один раз. Сами вопросы приходят с сайта.

## 14 ноября 2026 — аудит сохранения и синхронизации

По просьбе пользователя проведён аудит без изменения логики сайта.
Сценарии воспроизведены на искусственных данных JavaScript-движком, личные
результаты пользователей не использовались. Исправления пока не внесены.

1. sync-state.js, replay(): все seed сначала объединяются, затем поверх
   проигрываются все patch. Поэтому seed второго устройства с более новым
   результатом карточки может быть перезаписан старым patch первого.
   Воспроизведение: seed A пустой, patch A last=100/reps=1, seed B
   last=300/reps=2. Итог last=100/reps=1.
2. Тот же порядок приводит к двойному учёту дневной статистики при пересечении
   seed и patch. Seed B с импортированной копией уже учтённого ответа (reviews=1)
   плюс прежний patch reviews:+1 дают reviews=2 вместо 1.
   Обе проблемы относятся к согласованию исходных снимков с журналом событий.
3. cloud-sync.js сравнивает before/result через JSON.stringify и при отличии
   очищает undoStack. Один и тот же результат с другим порядком полей приводит
   к очистке отмены ответа. Мок серверного callback подтвердил: длина undoStack
   1 -> 0 при семантически одинаковом прогрессе. Firestore сортирует ключи map
   (подтверждено официальной документацией Supported data types).
4. store.set() во всех пяти страницах подавляет ошибки localStorage.
   Смоделированный QuotaExceededError не возвращает признак отказа и не бросает
   ошибку вызывающему коду. В офлайне при отказе хранилища ответ может остаться
   только в памяти до закрытия страницы.

Приоритет: согласование seed/patch и защита актуального прогресса, затем
сравнение данных без зависимости от порядка полей и обработка ошибок записи.
Это точечный аудит перечисленных сценариев, не исчерпывающая проверка сайта.
Публикация не выполнялась.

  включая удаления. Свежие снимки прогресса больше не перекрываются более
  старыми событиями; устаревшие снимки не воскрешают удалённые карточки.
- Итоговые счётчики старых seed объединяются по максимуму в момент их
  появления в истории, поэтому пересекающийся бэкап не начисляет повторно
  уже проигранные ответы. Последующие независимые patch суммируются.
  У legacy seed нет сведений о происхождении каждого ответа: точно отличить
  независимые старые занятия от перекрывающихся копий невозможно. Для них
  принят консервативный максимум; полная реконструкция старой статистики
  без первичного журнала ответов не гарантируется.
- Новые patch содержат эпоху reset; изменения из старой эпохи не проходят
  поверх нового сброса. Старые документы без поля reset поддерживаются.
- Сравнение состояния и создание patch теперь используют рекурсивное
  сравнение значений без зависимости от порядка полей. Облачное подтверждение
  собственного ответа сохраняет отмену. При реальном удалённом изменении
  отмена сбрасывается только для затронутых карточек; глобальный reset очищает её.
- Общий progress-storage.js включён во все пять страниц занятий.
  Запись трёх ключей делается с восстановлением предыдущих значений при отказе.
  Ошибки чтения и записи показываются предупреждением с повтором и экспортом.
- Cloud сохраняет неподтверждённые события также в памяти при отказе localStorage,
  удерживает их поверх серверного снимка и повторяет с прежним id.
  Статус «Синхронизировано» не скрывает ошибку локального сохранения.
